# تحديث نظام الأدوار والصلاحيات — دليل النشر

## ما الذي تغيّر
- **كل مسارات `/api/*` (50 مساراً) صارت محمية على الخادم** بالجلسة والصلاحية، لا بالواجهة وحدها. الاستثناء الوحيد: `evolution/webhooks` (يستدعيه Evolution نفسه).
- **57 صلاحية بأسماء عربية مفصلة** (أُضيفت 15 صلاحية دقيقة: إرسال المرفقات، تحويل الرسائل، حذف عند الجميع، تغيير الحالة، الاستطلاعات، طلب/اعتماد الصلاحيات، حذف/دمج جهات الاتصال، الردود الجاهزة، الوسوم، قرارات انضمام المجموعات، مزامنة المجموعات، إرسال الإشعارات).
- **نطاق الخط والمحادثة**: لا يقرأ الموظف ولا يرسل إلا من خطوط `line_access` المصرّح له بها، ولا يرى محادثة زميل إلا بـ«رؤية جميع المحادثات» أو بطلب معتمد.
- **الهوية من الجلسة**: المفضلة والإشعارات والتثبيت وإيصالات القراءة وطلبات الصلاحيات وقراراتها تُنسب لصاحب الجلسة، لا لما يرسله العميل. أُزيل معرف الموظف الثابت في المفضلة/التثبيت، وأُزيل استثناء «أي بريد يحتوي ayman» من `/api/inboxes`.
- **التواقيع**: من لا يملك `signature.manage` يعدّل توقيعه الشخصي فقط (إن سُمح له) ولا يغيّر الأعلام.
- **الواجهة** تُخفي الأزرار التي لا يملكها الموظف (استيراد/تصدير/دمج/حذف جهات الاتصال، إرفاق ملف، حذف للجميع، تحويل، تغيير الحالة).
- **مدير النظام الأعلى** يتجاوز الفحص دائماً (يشمل أي صلاحية جديدة).

## خطوات التحديث على السيرفر (بهذا الترتيب)

### 1) قاعدة البيانات (Supabase → SQL Editor) — قبل نشر الكود
شغّل بالترتيب (آمنة للتكرار):
1. `db/post_fix/0015_roles_security_arabic.sql` (إن لم تُشغَّل سابقاً)
2. `db/post_fix/0016_permissions_expansion.sql`

الملف 0016 يمنح الصلاحيات الجديدة تلقائياً للأدوار التي كانت تقوم بالعمل نفسه ضمناً (مثلاً: من يملك الرد يحصل على إرسال المرفقات)، فلا ينقطع عمل أحد.

### 2) تأكد من تصاريح الخطوط قبل التشغيل
فحص الخطوط يُطبَّق على غير المدير الأعلى. نفّذ هذا الاستعلام، وكل موظف يظهر فيه بلا خط لن يرى محادثات:
```sql
select s.full_name, r.key as role, count(la.line_id) as lines_count
from hub.staff s
left join hub.roles r on r.id = s.role_id
left join hub.line_access la on la.staff_id = s.id and la.can_read
where s.status = 'active' and r.key <> 'super_admin'
group by 1,2 order by lines_count;
```
أضف التصاريح الناقصة من صفحة الموظفين («الخطوط المسموحة»). **للنشر التدريجي** يمكنك تعطيل فحص الخطوط مؤقتاً بإضافة `LINE_ACCESS_MODE=off` في `.env` على السيرفر (باقي الحمايات تبقى فعّالة)، ثم إزالته بعد تعبئة التصاريح.

### 3) الكود
حدّد أولاً الفرع الذي يعمل عليه السيرفر ثم ادمج فيه:
```bash
cd /opt/tripyou-chathub        # أو /opt/resvbar-hub حسب موضع المشروع عندك
git branch --show-current       # الفرع الذي يعمل عليه السيرفر
git fetch origin
git merge origin/fix/roles-security   # أو ادمج الـ PR على GitHub ثم git pull
docker-compose -f docker-compose.hub.yml build --no-cache hub-web
docker-compose -f docker-compose.hub.yml up -d --force-recreate hub-web
```
(الأمر `docker compose` بدل `docker-compose` إن كان هو المثبّت عندك.)

### 4) بعد النشر
- اطلب من كل الموظفين **تحديث الصفحة وتسجيل الدخول مجدداً مرة واحدة** (الواجهة تكتب كوكي الجلسة الذي يقرؤه الخادم).
- تغييرات الصلاحيات تسري خلال 20 ثانية كحد أقصى (ذاكرة مؤقتة قصيرة).

## اختبار الصلاحيات
```bash
npm install
npm run test:permissions
```
127 حالة تغطي: بلا جلسة، حساب معلّق، مشرف، موظف دعم، مراقب، متدرب، وموظف باستثناءات فردية (سماح/منع) — تشمل نطاق الخط وملكية المحادثة والإسناد وتغيير الحالة والموافقات والتواقيع. الاختبار يعمل بقاعدة وهمية (لا يلمس بيانات حقيقية).

## قائمة فحص يدوي سريعة بعد النشر
| الدخول بحساب | يجب أن | يجب ألا |
|---|---|---|
| موظف دعم | يرى محادثات خطوطه ويردّ ويرفق | يرى «مسح كل جهات الاتصال» أو يفتح صفحة الأدوار |
| مراقب جودة | يقرأ فقط | يرسل رسالة أو يغيّر حالة |
| مشرف | يسند ويعتمد الطلبات | يحذف خطاً أو يغيّر صلاحيات الأدوار |
| بلا تسجيل دخول | — | يحصل على أي بيانات من `/api/*` (يعيد 401) |

- شاشة استثناءات الموظف (سماح/منع فردي) غير مبنية بعد؛ الجداول والفحص على الخادم جاهزان.
- توحيد `roles.json` مع أدوار القاعدة الفعلية (`sales_lead`, `observer`, `trainee`).
