# inbox/claude-c — مهمتك: HUB-012 (مواصفة فقط، بلا كود)
مجلدك: docs/specs. المخرج: docs/specs/outbound-router.md. المراجع: docs/00-PLAN.md §3 و§10 إلى §12، db/migrations (0002 و0004)، coordination/DECISIONS.md.

## ما يجب أن تغطيه المواصفة
1. مسار كل إرسال (Hub-first): فحص الخط المسموح (`line_access` + الصلاحية `inbox.reply`/`inbox.send_as`)، حالة الخط (متصل/محظور)، التوقيع (`signature_settings` وأجزاؤه الثلاثة)، سياسة مالك المجموعة (`ingest_owner_line_id` و`send_mode`)، SendGovernor (حدود، تأخير عشوائي، تسخين).
2. منع تكرار رسائل المجموعات المشتركة بين رقمين (`message_ledger` وصدى الرسالة من خط غير المالك يُعتبر صادراً).
3. التكامل مع Evolution API v2.3.7 (تعطيل signMsg، مسارات الإرسال، أحداث الـ webhook، حدود الاستعلام وrate-overlimit) وChatwoot 4.16 (محادثات API channel، الرسائل الصادرة، الإسناد).
4. المحادثة الجديدة بعد التفويض: متى تُنشأ (عند الموافقة أم عند أول إرسال)، ربطها بالأصلية (`conversation_links.linked_to_id`)، منح الرؤية للمحادثة فقط (`conversation_access_grants`)، وتفاصيل صلاحية التفويض 60 دقيقة (`send_as_grants`).
5. **سؤال التحقق الأهم:** هل يمكن فرض "المسند فقط" والاستثناء على مستوى المحادثة داخل iframe لـ Chatwoot 4.16، أم نحتاج عرض محادثات أصلياً في Hub؟ (Q-006). اذكر ما تتحقق منه من التوثيق وما يحتاج تجربة.
6. المخاطر (حظر الأرقام، rate-overlimit، تضارب الأرقام المشتركة) والأسئلة المفتوحة بقائمة واضحة، وما يجب أن يقرره المنسق أو المستخدم.
- بلا كود تنفيذي (مخططات تسلسل نصية مقبولة). لا مفاتيح ولا وصول لسيرفر.
